# وضعیت آمادگی اتصال احراز هویت PHP به رابط کاربری

تاریخ بررسی: 2026-11-17  
شاخه بررسی‌شده: `migration/php-mysql`

## نتیجه

اتصال AuthProvider به PHP API در این شاخه هنوز قابل انجامِ امن و قابل‌تست نیست؛ چون فایل‌های رابط کاربری و احراز هویت سورس اصلی در خود شاخه وجود ندارند. این محدودیت با خطای کامپایل یا باگ برنامه یکی نیست؛ فایل‌های موردنیاز اساساً در درخت فعلی شاخه حاضر نیستند.

## موجودی تأییدشده شاخه

در فهرست فعلی شاخه، مسیرهای سطح بالا شامل موارد زیرند:

- `README.md`
- `docs/`
- `src/lib/api/`

در `src/lib/api/` فقط کلاینت PHP افزوده‌شده در مرحله قبل موجود است. مسیرهای زیر در شاخه فعلی پیدا نشدند:

- `src/lib/auth/provider.tsx`
- `src/lib/auth/use-current-user.ts`
- `src/lib/auth/client.ts`
- `src/lib/auth/gates.tsx`
- `src/lib/auth/middleware.ts`
- `src/routes/__root.tsx`

بنابراین نمی‌توان امضای واقعی provider، نوع کاربر، قرارداد session یا محل مصرف auth را از روی این شاخه بررسی کرد. ساختن فایل جایگزین با حدس‌زدن این قراردادها ممکن است به سورس اصلی آسیب بزند یا مسیر ورود ظاهراً موفق اما غیرعملی بسازد.

## کارهای انجام‌شده در این مرحله

- درخت شاخه `migration/php-mysql` از GitHub خوانده شد.
- مسیرهای موردنیاز برای اتصال auth بررسی شدند و نبود آن‌ها در شاخه فعلی تأیید شد.
- هیچ تغییری در `main` یا فایل‌های سورس اصلی اعمال نشد.
- هیچ اتصال ناقص یا mock برای احراز هویت ساخته نشد.

## دروازه لازم پیش از پیاده‌سازی

1. انتقال کامل سورس اصلی برنامه به شاخه مهاجرت، بدون جایگزین‌کردن آن با ZIPهای ناقص.
2. تطبیق دقیق نسخه منتقل‌شده با آرشیو اصلی و ثبت checksum فایل‌ها.
3. بازخوانی provider، صفحه ورود، guardها، routeها و همه مصرف‌کنندگان auth.
4. طراحی تغییرات کوچک و سازگار با نوع‌های واقعی پروژه.
5. اجرای typecheck و تست ورود/خروج و نقش‌ها در محیط قابل ساخت؛ سپس آزمون PHP session و CSRF روی staging.

## معیار پذیرش اتصال احراز هویت

- هیچ درخواست عملیاتی به Better Auth یا runtime قدیمی وابسته نباشد.
- وضعیت ورود فقط از PHP session سمت سرور بازیابی شود.
- cookie نشست HttpOnly باشد و CSRF در درخواست‌های تغییردهنده بررسی شود.
- نقش کاربر از پاسخ معتبر سرور بیاید؛ نقش ذخیره‌شده در localStorage مجوز ایجاد نکند.
- صفحات و عملیات بر اساس نقش‌های مدیر، صندوق‌دار و آشپزخانه محافظت شوند.
- خروج و تغییر رمز/نقش، نشست‌های مربوط را به‌درستی بی‌اعتبار کنند.
- تست‌های موفق و ناموفق ورود، نشست منقضی، CSRF نامعتبر و دسترسی غیرمجاز ثبت شوند.

## وضعیت انتشار

این شاخه هنوز یک snapshot کامل از برنامه نیست. تا انتقال کامل سورس و گذر از تست‌های یکپارچه، ZIP یا deploy برای staging/production تولید نشود.
