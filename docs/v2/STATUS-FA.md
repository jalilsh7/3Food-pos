# وضعیت اجرایی 3Food POS V2

آخرین بازبینی ساختاری: 2026-11-22  
شاخه مبنای توسعه در زمان بازبینی: `feature/3food-pos-next-release-v2`

## معماری و قابلیت‌های موجود در سورس
- ورود و نشست سمت سرور با PHP؛ راه‌اندازی مدیر اولیه با setup token یک‌بارمصرف و کنترل نقش‌های manager، cashier و kitchen.
- داده عملیاتی مبتنی بر MySQL؛ bootstrap و API برای منابع POS.
- ثبت سفارش با شماره ترتیبی سرور و کلید idempotency؛ اعتبارسنجی قیمت، تخفیف و مالیات در سمت سرور.
- ثبت اثرهای سفارش بر موجودی مواد اولیه و وفاداری مشتری در تراکنش و بازگردانی کنترل‌شده اثرها هنگام لغو.
- کنترل دسترسی منابع و عملیات بر اساس نقش.
- پشتیبان‌گیری و بازیابی مدیرمحور؛ restore فقط روی دیتابیس عملیاتی خالی و با حفظ حساب‌ها/نشست‌ها/audit مقصد.
- همگام‌سازی دوره‌ای UI با bootstrap سرور؛ polling حدود ۱۵ ثانیه‌ای، نه همگام‌سازی بلادرنگ.
- ارسال SMS از API سمت سرور با تنظیمات خصوصی؛ گزارش ارسال در لاگ.
- تنظیمات ظاهر سراسری و بسته‌بندی استاتیک cPanel در مسیر `npm run build:cpanel`.

این موارد بر اساس سورس و مستندات موجود فهرست شده‌اند؛ هر مورد باید در محیط هدف نیز آزمون پذیرش شود.

## تصمیم‌های قطعی دامنه V2
- نیاز عملیاتی فروشگاه: **یک صندوق**. چندصندوقی و مدیریت چند صندوق فروشگاهی جزو نیازمندی‌های این نسخه نیست.
- نقش‌های مدیر، صندوق‌دار و آشپز و محدودیت دسترسی آن‌ها حفظ شود.
- V2 از V3 مستقل بماند.
- قابلیت کارتخوان شبکه‌ای موجود در سورس صرفاً زیرساخت پایه است؛ تا زمان وجود درایور تأییدشده و آزمون دستگاه واقعی، نباید پشتیبانی عملیاتی آن ادعا شود.

## موانع باز پیش از استفاده روزمره
1. استقرار روی staging واقعی cPanel/LiteSpeed با همان PHP، PDO MySQL و نسخه MySQL هاست مقصد.
2. آزمون کامل ورود، خروج، ساخت مدیر اولیه و ماتریس مجوزهای نقش‌ها.
3. آزمون جریان واقعی سفارش، محاسبه مبلغ، تخفیف/مالیات، لغو، موجودی و وفاداری با MySQL واقعی.
4. آزمون ارسال و دریافت واقعی پیامک با اعتبارنامه معتبر پنل؛ بررسی ثبت موفق/ناموفق در لاگ و اطمینان از اینکه خطای پیامک سفارش را متوقف نمی‌کند.
5. آزمون backup و restore روی دیتابیس آزمایشی خالی و تأیید بازیابی سفارش‌ها و ledgerها.
6. آزمون قطع و وصل شبکه، refresh، polling و جلوگیری از سفارش تکراری.
7. آزمون پذیرش فروشگاهی با یک صندوق، ابتدا با داده آزمایشی و سپس دوره کوتاه بهره‌برداری تحت نظارت.

## وضعیت ادعاها
- «در سورس وجود دارد» با «تست CI موفق» یکسان نیست.
- «تست CI موفق» با «تست staging واقعی» یکسان نیست.
- «ساخت بسته» با «استقرار روی هاست» یکسان نیست.
- تا عبور از موانع بالا، V2 را نسخه آماده staging بدانید، نه نسخه تأییدشده برای کار روزمره فروشگاه.
