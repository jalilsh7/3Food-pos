# راهنمای راه‌اندازی پیامک 3Food POS V2

این راهنما مخصوص نسخه PHP API روی هاست است. اطلاعات اتصال پیامک در فایل خصوصی سرور ذخیره می‌شود و نباید در کد فرانت‌اند، خروجی پشتیبان یا مخزن Git قرار بگیرد.

## ۱) پیش‌نیازهای هاست

- PHP 8.1 یا بالاتر
- اتصال خروجی HTTPS به `rest.payamak-panel.com`
- افزونه PHP cURL (پیشنهادی و مسیر اصلی انتقال)
- امکان نوشتن فایل در پوشه خصوصی `php-backend/private` برای ذخیره تنظیمات
- IP خروجی هاست باید در پنل ملی‌پیامک مجاز شده باشد؛ خطای 109 معمولاً به همین موضوع مربوط است.

## ۲) تنظیم اتصال

از مسیر «تنظیمات فروشگاه ← اتصال ملی‌پیامک» موارد زیر را وارد کنید:

- فعال‌سازی سرویس
- نام کاربری پنل
- روش احراز هویت: رمز عبور یا ApiKey
- رمز/ApiKey متناظر با روش انتخاب‌شده
- شماره فرستنده اصلی برای پیامک‌های عادی
- شماره‌های پشتیبان اول و دوم SmartSMS (اختیاری)

با تغییر روش احراز هویت، باید اعتبارنامه همان روش جدید را وارد کنید. خالی گذاشتن فیلد فقط برای حفظ اعتبارنامه فعلی و بدون تغییر روش مجاز است.

فایل `php-backend/private/sms-config.php` به‌صورت خودکار ایجاد می‌شود. این فایل را عمومی نکنید و در دسترس وب قرار ندهید.

## ۳) دو مسیر کاملاً مجزا

### پیامک عملیاتی / خدماتی

- Endpoint: `/api/SendSMS/BaseServiceNumber`
- نیازمند `bodyId` عددی و تأییدشده از پنل ملی‌پیامک
- مقدار `text` فقط مقادیر متغیرهاست؛ مقادیر با `;` از هم جدا می‌شوند و باید دقیقاً به ترتیب متغیرهای الگو باشند.
- رویدادهای پشتیبانی‌شده: ثبت سفارش، آماده‌شدن، تحویل، کسب امتیاز و استفاده از کد تخفیف.
- اگر `bodyId` تنظیم نشده باشد، ارسال عملیاتی متوقف می‌شود و به خط شخصی تغییر مسیر نمی‌دهد.

### پیامک عادی / کمپین

- Endpoint: `/api/SmartSMS/Send`
- از شماره فرستنده شخصی فروشگاه استفاده می‌کند.
- `bodyId` نمی‌پذیرد و به مسیر خدماتی تغییر مسیر نمی‌دهد.
- کمپین و درخواست ثبت تاریخ تولد فقط برای مشتری دارای `smsConsent === true`، `smsConsentConfirmed === true` و شماره معتبر منطبق با پرونده مشتری ارسال می‌شود؛ API سرور هر سه شرط را دوباره بررسی می‌کند.
- ارسال گیرندگان کمپین ترتیبی است و نتیجه هر گیرنده در سوابق پیامک ذخیره می‌شود.

## ۴) قالب‌های خدماتی

شناسه الگو را خود پنل ملی‌پیامک صادر می‌کند؛ POS شناسه جدید تولید نمی‌کند.

نگاشت متغیرهای عددی:

| متغیر | مقدار |
|---|---|
| `{0}` | شماره سفارش |
| `{1}` | نام مشتری |
| `{2}` | مبلغ کل |
| `{3}` | امتیاز |
| `{4}` | کد تخفیف |
| `{5}` | مانده |
| `{6}` | نام فروشگاه |

مثال الگو: `سفارش {0} ثبت شد.`

در زمان ارسال، برای این مثال فقط مقدار شماره سفارش ارسال می‌شود؛ متن کامل رندرشده به‌جای متغیرها ارسال نمی‌شود.

## ۵) تفسیر خطاهای رایج

- کد 4: شناسه الگوی خدماتی نامعتبر یا تأییدنشده است.
- کد 5: تعداد یا ترتیب متغیرها با الگو مطابقت ندارد.
- کد 109: IP خروجی هاست باید در پنل مجاز شود.
- کد 110: روش احراز هویت را بررسی کنید و در صورت نیاز ApiKey معتبر وارد کنید.

## ۶) گزارش و معنای موفقیت

سوابق در منبع `sms_logs` دیتابیس POS ذخیره می‌شوند. وضعیت «پذیرفته‌شده» به معنی قبول درخواست توسط سرویس پیامک است و به‌تنهایی تحویل نهایی به گوشی را ثابت نمی‌کند؛ برای تأیید تحویل باید گزارش دلیوری سرویس‌دهنده نیز بررسی شود.

## ۷) نکته امنیتی رضایت

نمایش پیش‌فرض تیک رضایت در فرم ثبت مشتری به‌تنهایی رضایت معتبر ایجاد نمی‌کند. برای مشتری جدید، وضعیت باید پس از تأیید مشتری توسط کاربر تغییر داده شود. رکوردهای قدیمی که فقط مقدار `smsConsent` دارند و تأیید صریح آن‌ها ثبت نشده، تا زمان تأیید دوباره وارد کمپین نمی‌شوند؛ برای تأیید مجدد، پس از موافقت مشتری وضعیت رضایت را دوباره ثبت کنید. لغو رضایت باید با برداشتن تیک ثبت شود.
