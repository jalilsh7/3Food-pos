# 3Food POS — PHP/MySQL backend migration (مرحله توسعه)

این بسته شامل زیرساخت PHP برای جایگزینی تدریجی سرویس Node.js و ذخیره‌سازی مرکزی MySQL است. **این بسته هنوز نسخه نهایی قابل استفاده در فروشگاه نیست**؛ ورود و ارسال پیامک React به APIهای PHP وصل شده‌اند، اما همگام‌سازی کامل داده‌های POS، منطق تجاری سفارش، انتشار استاتیک و آزمون نهایی هاست هنوز باقی است.

## نیازمندی‌ها
- PHP 8.2+ (حداقل کد PHP 8.1)
- افزونه‌های `PDO` و `pdo_mysql`
- MySQL 5.7.8+ یا MariaDB سازگار با JSON و InnoDB
- Apache با `mod_rewrite` و پشتیبانی `.htaccess`
- SSL فعال

## ساختار و نصب آزمایشی
1. در cPanel دیتابیس MySQL و کاربر اختصاصی بسازید و دسترسی کامل را فقط به همان دیتابیس بدهید.
2. `schema.sql` را در phpMyAdmin وارد کنید. اگر دیتابیس را قبلاً با نسخه قدیمی‌تر ساخته‌اید، فایل `migrations/002-session-version.sql` را نیز یک‌بار اجرا کنید.
3. `private/config.example.php` را به `private/config.php` کپی کنید و اطلاعات دیتابیس را وارد کنید.
4. برای `app_key` و `setup_token` دو مقدار تصادفی مستقل با حداقل 64 نویسه hex تولید کنید. از قرار دادن آن‌ها در پوشه عمومی یا JavaScript خودداری کنید.
5. برای پیامک، فقط در `private/config.php` مقدار `sms.provider` را `national_payamak` و مقادیر `username`، `password` و `sender` را تنظیم کنید. این اطلاعات را در تنظیمات مرورگر یا فایل‌های Git قرار ندهید.
6. Document Root زیردامنه را روی `php-backend/public` قرار دهید؛ پوشه `private` باید بیرون Document Root باشد.
7. SSL را فعال کنید.
8. `GET /api/v1/health` را بررسی کنید.
9. در صفحه ورود POS، راه‌اندازی اولیه را انجام دهید و توکن یک‌بارمصرف را وارد کنید. رمز باید حداقل 12 نویسه باشد.
10. پس از ایجاد مدیر، مقدار `setup_token` را از `private/config.php` حذف کنید.

## APIهای پیاده‌سازی‌شده
| Method | Path | دسترسی | توضیح |
|---|---|---|---|
| GET | `/api/v1/health` | عمومی | سلامت API و اتصال MySQL |
| GET | `/api/v1/setup/status` | عمومی | اعلام اینکه راه‌اندازی اولیه لازم است یا نه |
| POST | `/api/v1/setup/manager` | توکن یک‌بارمصرف | ایجاد مدیر اولیه و شروع نشست مدیر |
| POST | `/api/v1/auth/login` | عمومی | ورود با نام کاربری و رمز |
| GET | `/api/v1/auth/me` | نشست | اطلاعات نشست جاری و CSRF |
| POST | `/api/v1/auth/logout` | نشست + CSRF | خروج |
| POST | `/api/v1/auth/change-password` | نشست + CSRF | تغییر رمز |
| GET/POST | `/api/v1/users` | مدیر | فهرست و ایجاد کاربران |
| PATCH | `/api/v1/users/{id}` | مدیر + CSRF | تغییر حساب کاربر |
| GET | `/api/v1/bootstrap` | کاربر واردشده | دریافت داده مرکزی و سفارش‌ها |
| GET/POST/DELETE | `/api/v1/records/{resource}` | براساس نقش | داده‌های دسته، محصول، مواد، مشتری، تخفیف، هزینه، تنظیمات، قالب پیامک و لاگ پیامک |
| POST | `/api/v1/orders` | مدیر/صندوق‌دار + CSRF | ثبت سفارش با شماره ترتیبی اتمیک و کنترل قیمت پایه محصول/افزونه در سرور |
| PATCH | `/api/v1/orders/{id}/status` | مدیر/آشپز + CSRF | تغییر وضعیت سفارش |
| POST | `/api/v1/sms/send` | مدیر/صندوق‌دار + CSRF | ارسال پیامک با اعتبارنامه خصوصی سرور |

نقش‌ها: `manager`, `cashier`, `kitchen`.

## نکات مهم و محدودیت‌های باقی‌مانده
- صفحه اصلی React اکنون ورود، راه‌اندازی اولیه مدیر، تغییر اجباری رمز و خروج را با نشست PHP انجام می‌دهد؛ انتخاب دستی نقش از رابط حذف شده است.
- داده‌های POS هنوز به‌طور کامل از Zustand/localStorage به MySQL منتقل نشده‌اند؛ قبل از استفاده واقعی باید همگام‌سازی همهٔ منابع، سفارش‌ها و انتقال امن داده‌های قدیمی پیاده‌سازی و آزمون شود.
- محاسبه کامل و قطعی تخفیف‌ها، مالیات و امتیاز وفاداری باید در سرور نهایی شود؛ فعلاً فقط subtotal سفارش با قیمت محصول و گزینه‌های ذخیره‌شده در سرور تطبیق داده می‌شود.
- کسر موجودی و مصرف recipe، لغو/بازگشت موجودی، گزارش‌ها، بکاپ/بازیابی و همگام‌سازی لحظه‌ای هنوز کامل نیستند.
- ارسال پیامک از مسیر PHP انجام می‌شود و اعتبارنامه از `private/config.php` خوانده می‌شود؛ رابط مرورگر فقط شماره، متن و شناسه الگو را می‌فرستد. فعال‌سازی واقعی نیازمند تنظیم اعتبارنامه و آزمایش ارسال در هاست است.
- فونت و assets خارجی و حذف نهایی Grok/Vercel از مسیر انتشار هنوز نیازمند تکمیل است.
- تغییرات اخیر هنوز با `php -l`، TypeScript، build و آزمون end-to-end روی هاست بررسی نشده‌اند. اتصال واقعی MySQL و ارسال پیامک نیز تا تنظیم cPanel تأییدشدنی نیست.

## بررسی نحوی
```bash
php -l public/api/index.php
```

**هشدار:** این بسته برای ادامه توسعه و تست staging است؛ آن را جایگزین نسخه عملیاتی صندوق نکنید.
